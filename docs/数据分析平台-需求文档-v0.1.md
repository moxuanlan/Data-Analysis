# DataLens 数据分析平台需求文档

应用暂定名称：DataLens。

版本：v0.1（需求评审稿）  
日期：2026-10-30  
状态：仅定义需求，不涉及功能实现。标注“建议”或“待确认”的内容不视为已确认决策。

## 1. 产品目标

建设一个通过浏览器访问、登录后使用的数据分析网站，供个人和团队完成数据导入（网页爬虫采集或自行上传数据）、数据查看、数据清洗、MySQL SQL 生成与脚本导出，以及可视化分析准备。

数据导入提供两个平等入口：网页爬虫采集、自行上传数据。用户选择爬虫时，提供目标网站和采集需求，系统真实访问网页获取数据；选择自行上传时，直接解析用户文件，无需创建爬虫任务。两种来源统一生成数据集，不以 AI 生成的内容替代原始数据。AI 用于理解需求、提出处理建议、辅助生成 SQL 和可视化参考内容。

典型场景：用户提供历史天气网站，说明城市、时间范围和所需字段，采集天气数据，查看结果，生成 MySQL 建表及导入脚本；后续清洗数据，分析温度变化，并获取可视化参考代码或 FineBI 所需数据。

用户也可以上传已有的历史天气数据，直接进入数据展示及后续分析，无需经过网页采集。

| 能力 | 已确认需求 | 版本安排 |
| --- | --- | --- |

## 3. 用户与共享

- 个人使用：查看和处理自己的任务、数据集及生成脚本。
- 团队使用：团队成员能够共享访问指定数据。
- 数据应标明个人或团队归属，非授权用户不能通过页面、接口或下载地址访问。
- 建议使用独立个人账号加入团队，避免多人共用密码；用户尚未确认此模式。
- 团队共享是否允许修改、删除、重新清洗及生成脚本，成员邀请和管理方式，均待确认。

## 4. 核心操作流程

1. 用户登录，进入自己的数据空间或团队共享空间。
2. 进入“数据导入”，选择“网页爬虫采集”或“自行上传数据”。
3. 爬虫入口：输入网址、自然语言需求和目标数量，确认字段及样例后分批采集；上传入口：选择文件，预览解析结果并确认导入。
4. 系统展示采集或导入进度、成功与失败数量，完成后生成统一数据集。
5. 用户查看字段、样例和数量，必要时进入清洗流程。后续能力与数据来源无关。
6. 用户按需求选择 SQL 生成与导出，或可视化分析；生成 SQL 不是可视化的前置条件。
7. SQL 路径中确认表名、字段类型或更新条件，预览并下载脚本；可视化路径中选择方案，获取参考代码或数据文件。

## 5. 数据导入

数据导入包含两条独立路径，均适用相同的数据归属、权限及后续处理规则。5.1—5.3 描述爬虫路径，5.4 描述自行上传路径。

### 5.1 输入与范围

采集任务输入包括网站地址、目标数据描述、目标数量，以及按需指定的时间、地区、字段和筛选条件。缺少影响采集范围的信息时，应提示补充，不能静默猜测。

“采集 10 万条”表示该任务的目标数量，不代表任意网站都能提供足量数据。系统应识别数据耗尽、重复分页、访问受限及解析失败等情况，报告实际数量和结束原因。

首版需在实现前确定验收网站及支持类型：普通 HTML、分页列表、动态加载网页、登录后页面是否支持尚待确认。不能承诺支持所有网站。遇到验证码、访问限制或无权访问的数据，应提示用户，不能将失败伪装成完成。

### 5.2 执行与批处理

- 一次提交后，系统按批次完成任务，不要求用户逐批发起。
- 建议后台执行，刷新或关闭浏览器不会丢失已保存结果。
- 显示任务状态、目标条数、已采集条数、失败情况及结束原因；无可靠总量时不显示虚假的百分比。
- 建议状态包含待执行、执行中、完成、部分完成、失败、已取消。
- 提供取消入口，保留已成功采集的数据；失败重试范围和断点续采能力待确认。
- 分批保存，避免把大任务全部积压到内存或浏览器中。
- 保存来源网址、采集时间和任务关联信息，便于追溯；重试不能无提示地重复写入同一批记录。
- 访问频率与并发需遵守目标网站规则，具体配置在确认网站和部署条件后确定。

### 5.3 完成反馈

任务结束展示请求数量、实际采集数量、失败情况及可用结果入口。只有达到目标或明确完成约定范围时，才能报告对应的完成状态；数据不足时报告部分结果与原因。

### 5.4 自行上传数据

- 用户选择本地数据文件，无需提供网站地址或运行爬虫。
- 首版建议支持 CSV、Excel（.xlsx）；最终格式、单文件大小和行数上限待确认，不能默认承诺支持任意文件。
- 导入前展示字段、样例和建议类型，允许确认表头；CSV 涉及编码及分隔符，Excel 涉及工作表选择时，应明确解析选项。
- 保留文本中的前导零、原始精度及空值语义；类型不确定或转换可能丢失信息时提示确认，不静默改写。
- 展示导入状态、成功行数、失败行数及错误原因，不能无提示丢弃解析失败的数据；是否允许跳过错误行由用户确认。
- 记录来源类型、原始文件名、导入时间及操作者，完成后进入统一数据集页面。
- 默认创建新数据集；追加或覆盖现有数据、自动合并多个文件暂不列为已确认需求。
- 上传文件仅作为数据解析，不执行宏、公式或内嵌代码；文件类型与大小校验规则随支持范围确定。

## 6. 数据展示

- 以表格分页展示采集或上传的数据，不一次向浏览器加载全部 10 万条记录。
- 展示数据集名称、来源类型及来源信息、采集或导入时间、记录数、字段名、字段类型和任务状态。
- 建议支持按字段排序、筛选和搜索，便于用户检查结果。
- 区分空值、空字符串和数值 0，长文本可展开查看。
- 从数据集进入 SQL 生成、清洗及可视化功能；未上线能力不显示为可执行功能。
- 原始采集或上传数据与后续清洗结果明确区分，避免用户误认数据来源。

## 7. 数据清洗（完整需求，建议第二阶段）

| 操作 | 用户需要确认的内容 |
| --- | --- |
| 去重 | 判断重复的字段、保留哪一条记录 |
| 补缺失值 | 涉及字段、固定值或统计填充规则；无法合理补齐时允许保留空值 |
| 日期格式统一 | 原始格式、目标格式、必要时的时区及解析失败处理 |
| 金额格式统一 | 小数精度、货币单位、千分位及无效值处理；不默认执行汇率换算 |
| 字段拆分合并 | 分隔规则、目标字段、原字段是否保留 |
| 异常值识别 | 判断规则、异常记录示例及标记或排除方式 |

AI 先提出建议，展示原因、影响行数及处理前后样例，用户确认后执行。建议保留原始数据并生成新的清洗版本，记录处理规则；具体版本保留及撤销方式待确认。

AI 不应把虚构值作为实测数据填入。例如天气缺失值如采用估算，应由用户确认并标明估算性质。

## 8. MySQL SQL 生成与脚本导出

### 8.1 通用要求

- 用户选择原始或清洗后的数据集及版本，明确生成范围是全部数据还是筛选结果。
- 生成前展示表名、字段映射、建议类型及必要参数，由用户确认。
- MySQL 具体版本待确认，语法应与最终指定版本兼容。
- 正确处理中文、引号、反斜杠、换行、NULL、日期和小数；不能把空值错误输出为字符串 'NULL'。
- 展示 SQL 预览、校验结果和脚本生成状态，不把截断的预览当成完整导出内容。
- 首版范围建议限定为生成与下载，不连接用户数据库自动执行；直接执行尚未获得用户确认。

### 8.2 CREATE TABLE

根据字段及数据特征建议 MySQL 字段类型，支持用户修改表名、字段名、长度、精度、可空属性及主键。主键和唯一约束不能未经确认自动推定；字段类型推断依据和可能不兼容的数据应可见。

### 8.3 INSERT

为选定数据生成导入语句，支持大量记录分批写入脚本。导出行数应与选定的数据范围一致，不得遗漏分页之外的数据。批大小、文件拆分阈值等由后续设计确定，不在本稿中预设。

### 8.4 SELECT

用户以自然语言描述分析需求，AI 根据真实表结构生成查询，覆盖筛选、排序、聚合及关联。例如“按月份统计某城市平均气温”。

不得编造表或字段。多表关联必须取得相关表结构及关联关系；信息不足时要求补充。若没有数据库执行环境，只报告生成及静态校验结果，不能声称查询已执行成功。

### 8.5 UPDATE

用户提供目标表结构、匹配键、更新字段及更新规则后生成脚本。无法确定匹配条件时，停止生成并要求补充；不默认生成无 WHERE 的全表更新语句。存在匹配键重复或为空时明确提示，避免误更新。

### 8.6 下载交付

支持下载 UTF-8 编码的 .sql 文件，建议可单独导出建表、导入、查询、更新脚本，并支持组合建表与导入脚本。文件标明生成时间、来源数据集及必要的执行前提；文件不包含 API Key 等凭据。

历史天气示例：按日期展示气温变化可推荐折线图，按月份比较降水量可推荐柱状图；需先确认实际字段和统计口径。以上 17 类方案构成候选范围，不局限于最初的 Python、ECharts 和 FineBI，也不要求每次向用户推荐全部方案。Python 方案可进一步选择 Matplotlib、Seaborn、Plotly、Bokeh 或 Altair 等库。

系统应结合分析目的、数据规模、时间或地理字段、交互需求、使用者编程能力及现有工具条件，推荐适合的方案并说明理由。候选清单不代表全部工具都需要自动集成：代码类交付参考代码及运行说明，手动操作类交付适配数据及操作指引；需要额外数据源、账号、部署环境或授权的方案，应明确使用前提，不能把普通数据文件描述成可直接打开的原生项目或报表。实际版本兼容性和导入格式在交付对应方案时验证。

导出格式建议支持 CSV，是否需要 Excel 待确认。程序内直接渲染交互图表、自动发布报表、自动撰写分析结论均未确认，暂不作为验收要求。

## 10. AI 服务接入

用户提供的接入文档：[腾讯元宝接入文档](https://docs.qq.com/doc/DWE54SHRMdkVnRXNK)。本次无法通过网页工具读取正文，尚未验证实际服务商、API 地址、模型、鉴权方式及协议，不能据此确认接口兼容性。

预期 AI 用途：理解采集需求、辅助字段识别与类型推断、提出清洗建议、生成 SQL、推荐可视化方案及参考代码。具体能力受接口实际支持情况约束。

建议密钥仅保存在服务端，不出现在浏览器代码、下载文件或普通日志中。由平台统一提供密钥还是用户自行配置，待确认。调用失败应明确提示，不影响已保存数据的查看和下载。

建议仅向模型传递任务所需的表结构、统计信息及有限样例，不默认上传全部 10 万条数据。外部模型的数据传输范围、调用预算和超限行为需在实现前确认。

网页内容与上传文件内容均视为待处理数据，不能作为系统指令执行；AI 生成 SQL 和代码也不能未经校验自动执行。

## 11. 页面与数据对象建议

页面采用满足主流程的最小集合：登录页、数据导入页（爬虫采集／文件上传）、任务列表与任务详情页、统一数据集与数据表格页、SQL 生成与导出页。清洗页、可视化建议与导出页按后续阶段增加；团队入口随身份模式确认。

核心数据对象包括用户、团队及成员关系、采集或文件导入任务、数据来源信息、数据集、字段定义、数据版本、清洗操作和 SQL 导出记录。这里只描述业务对象，不确定数据库表设计或技术栈。

## 12. 非功能要求

- 数据隔离：个人及团队权限须覆盖数据读取、任务操作、生成脚本和文件下载。
- 采集安全：用户输入 URL 应校验；服务端采集不得访问内部网络、云服务元数据等非授权地址，重定向也需检查。
- 展示安全：网页采集及文件导入内容按数据展示，避免执行原网页中的脚本。
- 大数据量：以 10 万条任务作为容量验收场景；实际耗时取决于网站、字段大小、限速及部署资源，不预先承诺固定完成时间。
- 可追溯：保留任务状态、失败原因、来源及用户确认的处理规则，日志避免记录密钥和不必要的原始数据。
- 数据保存期限、备份、删除机制、团队配额及同时运行的任务数量待确认。

## 13. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 登录与隔离 | 未登录不可访问业务数据；非授权账号不能读取他人或其他团队的数据与脚本 |
| A02 | 真实采集 | 在约定测试网站采集指定字段，抽样与来源一致，可追溯来源及采集时间 |
| A03 | 10 万条批处理 | 在具备足量数据且允许采集的测试源完成目标数量，无因批次重试造成的额外重复写入，导出无分页遗漏 |
| A04 | 数据不足或访问失败 | 展示实际数量和明确原因，不伪报达到目标；已保存结果可查看 |
| A05 | 数据展示 | 分页查看字段和值，记录数与保存结果一致，正确区分空值和 0 |
| A06 | 建表及导入 | 在最终指定版本的隔离 MySQL 测试库执行导出脚本成功，行数及抽样值与选定数据一致 |
| A07 | 查询生成 | 对已知测试表生成筛选、聚合和关联查询，字段有效，测试结果符合约定统计口径 |
| A08 | 更新生成 | 有明确匹配键时只更新目标记录；缺少条件时要求补充，不生成无条件更新 |
| A09 | 特殊值导出 | 中文、引号、反斜杠、换行、NULL、日期和小数经导入后符合预期 |
| A10 | AI 故障 | AI 超时或调用失败时有明确提示，已保存数据仍可访问 |
| A11 | 文件导入 | 在约定格式内完成上传、预览及导入，字段、行数与原文件一致，解析失败有明确反馈 |
| A12 | 双入口一致性 | 同一测试数据分别经爬虫与上传形成数据集，均可展示及生成 SQL，上传路径不依赖爬虫任务 |
| B01 | 清洗确认 | 用户确认前不修改结果，确认后影响范围与预览一致，原始数据可追溯；采集与上传数据均覆盖 |
| C01 | 可视化交付 | 参考代码与实际字段一致并可按说明运行；FineBI 数据文件可在约定版本中导入；采集与上传数据均可进入此流程，无需先导出 SQL |

A 类为首版验收，B/C 类为后续完整需求验收。测试数据源、部署条件及性能指标需在实施前约定。

## 14. 建议开发阶段

1. 需求与接口确认：确定团队身份模式、验收网站、MySQL 版本及 AI 接口能力。
2. 首版闭环：登录及数据隔离、数据导入双入口（一次性批量采集及文件上传）、数据展示、四类 SQL 生成与下载；通过 A 类验收。
3. 数据清洗：实现已确认的清洗类型及用户确认流程；通过 B 类验收。
4. 可视化支持：推荐方案、提供参考代码和导出数据；通过 C 类验收。

## 15. 实现前待确认事项

1. 团队采用共享登录账号，还是每人独立账号加入团队？成员分别有哪些权限？
2. 首版优先支持哪些网站？是否包含动态加载或登录后页面？请提供代表性链接。
3. 目标 MySQL 版本是什么？是否接受首版只生成和导出、不直接连接执行？
4. SELECT 关联和 UPDATE 所需的已有表结构，通过手动填写、上传建表 SQL，还是数据库连接提供？
5. 请补充可读取的 AI 接口文档内容；密钥由平台提供还是用户配置？
6. 是否接受清洗和可视化分阶段交付？首版四类 SQL 是否全部需要？
7. 自行导入是否优先支持 CSV 和 Excel（.xlsx）？单文件大小及行数上限如何确定？
8. 部署位置、用户数量、预算、数据保存期限和期望完成时间是什么？

这些问题不阻止本稿用于需求评审，但相关实现不得把建议擅自当作已确认要求。
